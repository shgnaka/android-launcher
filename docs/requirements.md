# Quiet Launcher 全体要件 v1.0

確定日: 2026-11-16。対象: 次の全体実装・受け入れ試験。ユーザーの「全体の要件を確定させて」に基づき、既回答と追加指示を統合し、残る技術的な境界を本書で固定した。外部ウィジェットの最低合格ライン3点は、同日のユーザー回答で個別に確定した。

本書が現行仕様の正本。[受け入れ計画](acceptance-plan.md) と [試験データ・計測方法](test-fixtures-v1.md) を合わせて用いる。過去の提案は [履歴](history/2026-11-16-pre-v1/) に保管する。凍結済みの [追加契約](contracts-2026-11-16.md) と既存テストは変更しない。本書はその契約を維持して詳細を補う。将来の変更は別の仕様改訂として扱う。

**要件の確定と、実装・検証の完了は別である。** 本書の「する」は製品が満たす義務を表す。現行APKが達成したという意味ではない。[実装・検証記録](nov16-validation.md) の未完了項目を取り消さない。今回追加した数値・境界のテストは、この要件から先に作成・凍結する。

## 1. 対象と初期状態

- 独自の製品ロジック、UI、保存、検索、Android連携をRustで実装する。独自Java/Kotlinアプリソースは追加しない。Android標準クラス、JNI、依存ライブラリとビルド用JDKは利用できる。試験用アプリにも同じ制約を適用する。
- Android 9〜15（API 28〜35）の個人領域を今回の対応範囲とする。基準実機は **OPPO Reno7 A / Android 13**。配布はarm64-v8a、エミュレーター試験はx86_64。API 36以降、ワークプロファイル、別ユーザー、メーカー独自の複製アプリ、ショートカット管理は今回対象外。
- アプリの同一性はパッケージ、起動先の同一性はパッケージ＋Activityで判断する。表示名や一覧の位置で同一性を判断しない。
- 初回はホーム登録・非表示・外部ウィジェット・追加読み・天気地域なし。文字100%、明るいテーマ、今日の画面時間、天気・画面時間・メディアの表示設定オン。天気地域なし・メディア対象なしではその内容を出さない。ホームには短い「＋ アプリを追加」を出す。自動の権限ダイアログや全面チュートリアルは出さない。
- 明暗は手動設定を保存する。OSテーマへの自動追従は今回対象外。日本語UI、24時間制 `HH:mm`、端末のローカル日付・曜日を使う。英語等のアプリ名は提供された名前を保持する。
- 部分一致・あいまい検索、手入力メモウィジェット、ウィジェットUIの完全再現、アプリロック、アンインストール操作、都市名検索、自動現在地取得、Fokus全機能の移植は今回対象外。

## 3. ホーム、表示量、文字サイズ

通常の表示順は時計、日付、電池、天気、画面時間、メディア、外部ウィジェット（追加順）、ホーム登録（ユーザー順）。自由配置は今回含めない。電池の値が取れないときは `電池 —` とする。時計と日付は前面復帰から1秒以内、前面表示中の分・日付の変化から1秒以内に更新する。

ホーム自体を縦スクロールさせない。設定には、現在の必要高さと利用可能高さ、文字サイズ、表示設定、登録の変更操作を示す。収まらないアプリ・ウィジェットの追加、再表示、情報表示の有効化、文字拡大は、保存前に判定し、**「ホームに収まりません」**を原因が読める状態で通知して反映しない。登録・順序・元の文字サイズを保持する。省略して登録だけ成功扱いにしない。

高さはシステムバー・切り欠き・アプリの余白を除いたdp単位の領域を使う。倍率をs、見える登録件数をnとした収容契約は次のとおり。凍結済み契約を維持する。

| 領域 | 確保する高さ |
| --- | --- |
| 時計・日付・電池・余白 | 144 × s |
| 天気、画面時間 | 各表示設定オンにつき24 × s |
| メディア | 表示設定オンなら84（対象なしでも追加時の収容予算は確保） |
| 外部ウィジェット | 登録1件につき48 × s |
| アプリ | n>0なら n × (max(48, 32 × s) + 8)、n=0なら追加操作48 |

天気やメディアの対象がないときは内容・枠・空のプレースホルダーを描画せず、後続の内容を詰める。上表の予約は、非同期で情報が現れても既存登録が突然収容不可にならないための上限判定である。文字を勝手に縮小しない。アプリ倍率は基準UIに対する倍率とし、OSの文字倍率を二重に掛けて画面と標準入力欄の大きさを食い違わせない。

回転・画面分割・旧設定・再インストールによる起動先の復活などで、保存済み構成が収まらなくなったときもデータを保持する。時計、短い収容不可エラー、設定への導線を表示し、登録項目の一部だけを正常表示扱いで出さない。設定では必要高さを減らす変更を受け付け、復元・キャンセルができる。元の正常構成に戻せる操作も提供する。

ウィジェットのホーム要約は見出し1行＋本文1行、長い名前・本文は末尾を省略し全文を設定で確認できる。これは文章の要約であり、登録項目そのものの無通知除外とは区別する。画面が極端に小さい場合もエラー・設定導線は可達にする。

## 4. 操作と画面状態

ホーム背景の長押しは設定を開く。ホームのアプリ名は通常タップだけで起動し、長押しで設定・操作メニュー・登録変更を起こさない。一覧では名前タップで起動、行末の＋／−で登録変更、名前長押しで「ホームに追加／ホームから外す」「非表示」「検索の読みを設定」を出す。

縦スワイプは移動48dp以上かつ縦移動が横の1.5倍以上で判定する。一覧を閉じる下方向は112dp以上とし、**指を置いた時点で先頭**の場合に限る。途中から先頭に着いた同一ジェスチャーでは閉じない。ホームから一覧が開く遷移は220ms、下から入る動きとする。長押しは500ms、10dp以上の移動でタップ・長押し候補を取り消す。慣性移動は画面端で停止し、別アプリを誤起動しない。タッチキャンセルと複数指の追加で、その操作のタップ候補を破棄する。

| 発生する操作・状態 | 戻り先・保持するもの |
| --- | --- |
| 一覧／IME入力中／長押しメニュー／設定／Quietの入力・確認画面でBack | 1回でホーム。検索語・一覧位置・メニュー・未確定入力・IMEを消す。保存済み設定は保持 |
| すでにホームでBack | ホームのまま。終了・別ランチャーへの遷移はしない |
| どのQuiet画面からでもHOME | ホーム。検索語・一覧位置・一時操作を消す。すでに前面でも適用 |
| 他アプリへ起動してからQuietへ復帰 | ホーム。既存一覧を即時利用し、世代確認は裏で行う |
| 新規プロセス起動 | ホーム。保存対象だけを復元し、検索語を復元しない |
| 画面回転・画面分割によるサイズ変更 | ホームへ戻す。保存対象を保持し、新しい寸法で収容判定 |
| 消灯・ロックからQuietへ復帰 | ホーム。メディア・画面時間等を更新 |
| Androidの権限／ウィジェット許可・提供元設定画面から復帰 | Quietはホームへ戻る。完了済みの外部結果だけ処理し、未完了・キャンセルを保存成功扱いにしない |
| メニュー外タップ、明示的なキャンセル | 現画面でメニュー／編集中入力を閉じる。保存値・検索語は変えない |

Backで破棄するのは未送信の編集入力。すでに開始した保存は結果まで処理し、成功した保存を取り消したように扱わない。画面遷移は保存待ちで停止させず、失敗はホームでも通知する。

「常にホーム」はQuietとQuiet所有の入力UI、またはQuietが再び前面になった時点の契約。他アプリ・Android標準画面が前面の間のBackで、その画面のAndroid標準動作を乗っ取ることはしない。IMEが先にBackを処理する経路でも、Quietの入力中にBackでIMEを閉じたらホームへ戻す。IMEの変換中も検査対象とする。IMEの「完了」やユーザーが明示的に入力を終了する操作はアプリのBackと区別する。

一覧を開いたらIMEを表示する。スクロール・メニュー・入力欄外タップでIMEを明示的に閉じた場合は一覧と検索語を保ち、再タップで再入力できる。プログラムによるIME閉鎖をBackと誤認しない。検索のEnterや変換確定だけでアプリを自動起動しない。

## 5. 一覧、起動先、キャッシュ

通常一覧は表示名をNFKC・小文字化したUnicode順、同じキーならパッケージとActivityの順とする。読み順・使用頻度順にはしない。空・空白だけの名前はパッケージ名で補う。同名行にはパッケージ、同じパッケージ内の同名起動先には短いActivity名を補助表示し、タップ先を区別できるようにする。

正常なキャッシュは初回フレームから使う。キャッシュなし・破損時は再生成し、「アプリを読み込み中」と0件を区別する。取得失敗は「取得できません」と再試行を出す。古い正常キャッシュがあれば保持し、更新失敗を通知する。壊れたキャッシュの再生成で設定・非表示を初期化しない。

起動時と前面復帰から1秒以内に軽い世代確認を開始する。前面中は変更通知、または最長2秒間隔の軽い世代確認を行う。起動先100／1,000件の通常条件で、変更の発生または復帰から5秒以内に新一覧を反映する。スクロール等の入力処理を更新より優先し、一覧・検索に変更通知を安全に反映する。背景での周期監視はしない。

世代・起動ユーザー・端末再起動識別・表示言語を検証する。同じ世代でホーム／一覧切替、検索、時計・天気・画面時間更新、プロセス再起動のたびに全件列挙しない。設定の明示「アプリ一覧を再取得」は世代に関係なく再生成できる。

永続キャッシュは識別子・名前・検証情報のみ。アイコン・スクリーンショット・起動済みアプリの内容は保持しない。メモリの一覧を画面間で共有し、索引は世代変更時に生成する。端末から消えた項目を新一覧から除き、登録先の識別子は勝手に別Activityに置き換えない。

存在しないホーム登録はホームに出さず、設定の「未インストールの登録」から確認・明示削除できる。非表示のものはそこへも出さず、専用非表示管理へまとめる。同じ起動先が復活したら登録を復用し、収まらない場合は第3節の明示エラーにする。起動直前にも非表示と起動先の有効性を確認し、失敗時は短い原因と再試行を出して再取得を要求する。

## 6. 非表示と順番

非表示はパッケージ単位。名称変更・新Activity・削除・再インストールで解除しない。別パッケージの同名アプリには適用しない。通常のホーム・一覧・検索・並べ替えから除く。専用管理以外に件数・特殊検索語による入口を設けない。

専用管理は非表示にした順に並べ、名前とパッケージを表示する。未インストールなら最後の名前と「未インストール」を表示し、名前を保存できていなければパッケージを使う。未インストールでも指定解除できる。通常一覧の全アプリキャッシュとは別に、非表示管理に必要な最後の名前を端末内で保持する。

ホーム順は隠れた項目の位置を保持した列として管理し、見える項目間の並べ替えは見える位置を交換する。見える項目の解除はその登録だけを削除し、新規追加は列の末尾。繰返しても重複させない。

| 初期順 | 操作 | 再表示後の順 |
| --- | --- | --- |
| A,B,C | Bを隠して解除 | A,B,C |
| A,B,C | Bを隠し、見えるA,CをC,Aへ交換 | C,B,A |
| A,B,C | Bを隠し、Aをホーム登録から解除 | B,C |
| A,B,C | Bを隠し、Dを追加 | A,B,C,D |
| A,B,C,D | B,Dを隠し、A,Cを交換 | C,B,A,D |

B,Dの解除順を変えても最終順は同じ。再表示で収容不可になる場合は再表示全体を拒否し、非表示指定と登録順を保持して収容不可エラーを出す。

QuietやAndroid設定を非表示にしても、背景長押しや権限設定の導線は利用できる。非表示はQuiet内の起動項目の整理であり、OSや他アプリからの利用制限ではない。登録済みの外部ウィジェットと情報設定は削除しない。ウィジェットの提供元選択は情報の管理として引き続き利用できる。

## 7. 読み検索

検索対象は表示名と追加読み。空語は全表示対象。結果順は通常一覧と同じ。一致した全起動先を返し、同名や同じ読みの候補を勝手に1件へ絞らない。非表示はエンジンの出力の後にも適用し、起動時にも再確認する。

正規化はUnicode NFKC、前後空白・英大小文字、かな／カナ、主なヘボン式／訓令式、促音・長音・半角カナを扱う。読み照合では空白とローマ字の区切りアポストロフィの有無を許容する。長音の省略・表記差で同じキーになるものはすべて候補として返す。元のアプリ名は正規化で改名しない。句読点・数字まで無条件に除去しない。

必須の双方向一致例は [試験データ](test-fixtures-v1.md) の検索表で固定する。組み込み英語名の最低辞書はLINE＝らいん、Chrome＝くろーむ、YouTube＝ゆーちゅーぶ、Gmail＝じーめーる、Google＝ぐーぐる。未知のブランドの発音は推測せず、一覧メニューの追加読みで対応する。追加読みは起動先単位で1つ、空欄で削除、前後空白を除き128文字まで。超過はエラーにして以前の値を保持する。

入力・削除・貼り付け・変換中の文字・確定文字に反応し、古い非同期結果が新しい語の結果を上書きしない。検索変更時は一覧先頭へ戻す。入力方式・エンジンを差し替えても、端末連携・登録・非表示・保存は同じ契約を使う。検索にネットワークや大規模辞書・モデルを常駐させない。

## 8. 天気

地点は設定から緯度・経度を入力する。有限な緯度−90〜90、経度−180〜180を受理し、不正値・NaN・無限大は保存前に拒否する。表示名は任意。都市名検索・位置情報権限は今回追加しない。取得元はOpen-Meteo、HTTPSを使用する。

表示は天気、摂氏の整数、実際の取得時刻。四捨五入は0.5を絶対値の大きい側へ丸める（19.5→20、−0.5→−1）。端末日付と異なる取得日時は日付も示す。APIの観測時刻と取得時刻を別に保持し、観測時刻を取得時刻で捏造しない。未知の天気コードは「天気不明」とし、気温が正常なら区別して表示できる。

| 状態・操作 | 必須動作 |
| --- | --- |
| 表示オフ／地域なし | 欄を描画せず天気通信なし |
| 地域の設定・変更、表示オン | 対象の初回取得を開始。前の地域の値を新地域の値として出さない |
| 正常取得後 | 同じ地点の値・観測時刻・取得時刻を端末内に保持し、再起動後に再利用 |
| 通常更新 | 前面中、最後の成功から30分以上なら取得。前面復帰時にも判定 |
| 失敗時 | 初回は `天気 —`。前回値があれば取得後24時間未満は値と `更新待ち` を表示。24時間以上は数値を止め `天気 —`。設定で原因・前回時刻・再試行を確認 |
| 再試行 | 前面中、失敗から5分以上空けて自動再試行。手動更新は即時。取得中の同じ要求はまとめる |
| 地域変更・解除／表示オフ中に応答 | 地点だけでなく要求世代も検査し、現在の要求と異なる結果を反映しない |

成功・失敗に関係なく同時要求は1地点につき1つ。接続・読取を含む要求期限は10秒。自動通信はQuiet前面中だけで、非表示後は新しい通信を開始しない。失敗で取得時刻を更新しない。経過時間の判定は端末時計の逆行で停止しないものとし、時刻変更を検知したら期限を再検証する。

観測時刻が取得時点より10分を超えて未来、3時間を超えて過去、温度が有限でない、必要な値が欠落した応答は取得失敗とする。同じ地点をA→B→Aと変更した場合も、前のAの応答で新しいAの結果を上書きしない。

## 9. スクリーンタイム

定義は既存の **画面がインタラクティブだった時間の概算** を維持する。SCREEN_INTERACTIVE／SCREEN_NON_INTERACTIVEの履歴を使う。ロック解除時間やアプリ別利用時間、Quietを表示していた時間へ変更しない。ロックの有無だけで時間を除外しない。

- 今日: 端末ローカル午前0時〜現在。直近24時間: 現在−86,400秒〜現在。暦日の長さと固定24時間を区別する。
- 履歴を時刻順に安定整列し、範囲外を切り、重複したOn/Offで二重加算しない。同時刻の境界で架空の正時間を作らない。確実にOnの開いた区間は現在まで数える。
- 境界前の履歴は最大7日前まで調べる。境界状態を決められない区間、再起動・シャットダウンで終了が不明な区間は足さない。既知区間だけの値を出す場合は「概算／履歴不足」と識別し、完全な一日の値と誤認させない。
- 許可なし・API失敗は `—`。状態を確定できない空の履歴も `—`。利用なしを履歴・端末起動状態から確定できたときに限り0分とする。集計の純粋関数が空入力で0を返すことだけを、取得成功の根拠にしない。
- 秒で合算した後に分未満を切り捨てる。今日／直近24時間のラベルを必ず併記する。権限取消・日付・タイムゾーン・時刻変更・範囲切替は前面で1秒以内に旧数値を無効にし、5秒以内に再計算結果または取得不可状態を出す。通常は前面中30秒以内に更新する。
- 画面オフ中の音楽を加算しない。端末停止や不明区間を推測で補わない。範囲切替前の古い非同期結果は捨てる。

## 10. メディア

他アプリの公開された有効なMediaSessionを対象にする。Androidの通知アクセス許可を設定から標準画面で取得する。取得可能なのはその許可範囲のセッションだけであり、すべての音声出力がセッションを持つと仮定しない。通知本文は読取り結果の保存・送信・表示に使わない。

対象なし、権限なし、状態取得失敗はホームのメディア欄を出さず、設定で理由と権限導線を確認できる。新しい対象と再生状態・対応操作・提供元・曲名を前面復帰から2秒以内、通知や取得可能な状態変更から1秒以内に反映する。取得不能な曲名を架空に埋めない。提供元名と状態は必ず識別する。

初回選択は再生中、バッファ中、一時停止の順。同順位はパッケージ、セッション識別子順。識別子で選択を維持し、列挙順変更で選択を変えない。複数対象はメディア領域内の左右スワイプで1つずつ切り替え、端で停止する。対象位置は記号（点等）と読み上げ説明で示す。縦の一覧遷移と競合させない。横移動48dp以上かつ縦の1.5倍以上で切替、スワイプ中にボタン操作を発火しない。

表示は最大2行（提供元＋曲名／状態）と操作行。大きな文字では情報を1行へまとめ、設定から全文を確認できるようにして84dpの予約内へ収める。前曲・再生／一時停止・次曲は描画した記号を使い、文字の「前へ」「次へ」を通常UIに出さない。操作名はアクセシビリティ説明に保持する。最小48dpの操作領域を確保し、倍率により収まらない場合は表示有効化を拒否する。文字倍率を理由に操作領域を縮めない。

対応するTransportControlsだけを選択対象へ送る。再生状態がPLAYINGなら一時停止記号、PAUSEDなら再生記号。BUFFERING／CONNECTINGは待機記号、未対応操作は無効表示または非表示とし送信しない。STOPPED／NONE／ERRORや破棄されたセッションは対象から除外する。外部アプリが対応すると宣言しながら操作を無視した場合は成功表示を捏造せず、確認した実状態を維持する。

選択対象が消えたら残る対象の初回優先規則で選び直し、0件なら欄を消す。消失と操作が競合した場合は他の対象へ操作を流さず、その操作は失敗にする。権限取消後は取得・操作を停止する。セッションのトークンや曲名を永続化せず、プロセス再起動後は再選択する。

## 11. 外部ウィジェット

### 表示と名前

AndroidのAppWidgetHostで実提供元へ登録する。追加順を維持し、ホームには見出し・本文の短い要約、設定には全文と状態を表示する。View階層の表示中TextViewの文字を深さ優先の順で取り、文字がないViewのcontentDescriptionを代替にする。非表示Viewと空文字を除き、同じ文字・説明文の重複は初出1つへまとめる。見出しと同じ本文を二重に出さない。

名前はAppWidgetProviderInfoのウィジェット固有ラベル、保存済みラベル、提供元アプリ名、`名前不明（提供元識別子）` の順に補う。本物のラベルが「ウィジェット」の場合はその正しい名前を使い、同名は提供元を補助表示する。取得できた名前を固定の一般名に置き換えない。

1件につき深さ32、512ノード、本文合計4,096文字までを抽出対象とし、超過は全文側で「一部省略」を明示する。ホームの本文は1行に要約し、全文へアクセスできる。画像・独自描画・WebView・コレクションの全内容・元ウィジェットのボタン操作は今回の対応保証に含めない。読み取れる文字がなければ名前と **「内容を表示できません」** を表示し、設定に理由を出す。他の正常ウィジェットを巻き添えにしない。

### 登録・状態変化

追加前にホーム収容判定。許可・初期設定が必要ならAndroid標準／提供元画面を使い、キャンセル・拒否はその仮登録だけを破棄する。既存の登録を変更しない。連続要求は1件ずつ扱い、追加途中のプロセス終了後は、許可・設定が完了したことを検証できるものだけ正式登録へ復旧し、それ以外は取り消して通知する。

保存とOS側IDの操作をまたぐ途中状態は端末内に記録する。保存失敗は既存設定を保持し、確保済みの仮IDを解放する。削除は設定から対象を外す保存を先に確定し、その後OSのIDを解放する。解放失敗は次回へ持ち越し、削除した項目を復活させない。古い更新・古い非同期結果も登録世代が違えば捨てる。

提供元削除やアクセス不可は登録・名前を保持し、「提供元を利用できません」と削除／再連携の導線を出す。再インストール時は古いIDを当然に有効扱いせず、再連携を検証する。バックアップからのID復元も同様で、無効なIDに別のウィジェットを勝手に結び付けない。

提供元から文字更新を受信できたら前面中2秒以内に反映する。背景では内容を連続読取りしない。前面復帰後は更新を要求し、既知の静的な標準TextView提供元は5秒以内に名前・本文を表示する。提供元自身がデータを更新しない場合、Quietが情報を生成したり現在値として時刻を偽らない。

### ユーザー承認済みの最低E2E合格ライン

1. 実提供元の正しい名前と既知の本文がホームに実表示され、画面OCRから確認できる。
2. Quietのプロセス停止・再起動後に同じ名前・本文が復元される。
3. 設定から削除すると名前・本文が実画面から消える。

上記3点を2026-11-16の回答で確定した。[確認記録](widget-acceptance-confirmation.md)。最低ラインは許可・設定キャンセル、非対応内容、ID復旧、複数項目の分離等の個別検査の代用ではない。更新反映は固定した受信イベントのロジック・画面検査で確認する。追加の実提供元を使う動的更新E2Eは任意の拡張試験とし、v1.0の必須合格条件へ後付けしない。

## 12. 保存、復旧、通信

保存対象はホーム登録・順序、非表示パッケージと最後の名前、情報表示設定、文字倍率、明暗、天気地点、画面時間の範囲、外部ウィジェットID・名前・追加順、追加読み。天気の取得済み値と一覧キャッシュは再生成可能な別データとして保持する。検索語、一覧位置、IME、開いたメニュー、メディアトークンは永続化しない。

設定は型・範囲・形式版を検証する。JSONは既存の平坦な項目を維持し、形式版は `schema_version: 1`、版指定がない従来形式は0として受け入れる。2以上の未対応版は上書きしない。旧版で存在しない新項目は既定値、廃止メモは無視して他の設定を保持。未知の任意項目は既知の版なら無視できるが、将来の未対応形式版は通常保存で上書きしない。非表示を含む重要項目が不正なら全設定を読み取り失敗として保護し、正常な一部だけで一覧を公開しない。二重の登録は初出を保持して整理するが、非表示指定を推測で解除しない。

変更は検証後に保存キューへ直列に入れ、保存成功時だけ表示状態へ確定する。保存中の対象は二重受付・起動を止める。他の変更は受付順に処理し、古い結果で新しい操作を巻き戻さない。各保存は完全な一時ファイルの同期・原子的な置換・必要なディレクトリ同期を行う。クラッシュ後の主設定は完全な旧版か完全な新版のいずれかで、途中のJSONを正常扱いしない。

正常保存のたびに直前の正常設定1世代を端末内バックアップへ保存する。初回は同じ内容を復旧用にも保存する。バックアップの保存に失敗したら通常保存も失敗にする。画面へ成功を返す前に必要な保存処理を完了する。OS側がエラーを返した時点で置換が完了している可能性がある場合は主設定を再検証し、「未確認」として復旧へ誘導し、メモリだけ前の値で保存成功を装わない。

読み取り失敗では元ファイルを初期値で上書きせず、ホームのアプリ・通常一覧・検索を停止する。時計と設定・復旧への導線は使える。復旧はバックアップを検証し、破損元を別名保存してから明示操作で行う。失敗時も元データを残す。正常バックアップがない場合は、失うデータを示した確認付きの「設定を初期化」を提供する。キャンセルやBackは元データを保持し、Backはホームへ戻る。初期化でも破損元を退避する。

復旧した外部ウィジェットIDの有効性はOSで再検証し、第11節へ従う。設定削除・Quietのアンインストール後の復元、端末間移行、クラウドバックアップ、エクスポート／インポートは今回保証しない。Androidの自動バックアップで本書外のデータ転送が起きない構成にする。

Quiet自身の通信は、天気表示オンかつ有効な地域があるときの、指定座標によるOpen-Meteo HTTPS取得だけを許す。アプリ一覧、非表示、読み、画面時間、通知・メディア、ウィジェット内容、診断ログを外部送信しない。ユーザーの検索語を天気APIへ送らない。自動テレメトリー・広告・遠隔診断は追加しない。提供元アプリ自身の通信はQuietの送信と区別する。ログにはこれらの私的内容を記録せず、試験用提供元の既知の文字だけを試験成果物へ記録する。

## 13. UI・性能の合格条件

### 寸法と操作

画面幅240／320／360dp、縦・横、画面分割、文字80／100／160%を検査する。必要な操作は48dp以上の対象領域。長文は横にはみ出さず、ホーム以外の管理・全文は縦スクロールで到達可能。ホームの収容不可は第3節のエラーにする。日本語の欠字・記号欠落を避け、ボタンやメディア記号に操作名を付ける。読み上げでフォーカスして押せることを代表ケースで検証する。ハードウェアキーボードでは文字入力・削除・Enter・Escapeを扱い、独自ショートカット体系は追加しない。

### 計測条件としきい値

基準実機OPPO Reno7 A / Android 13のreleaseビルド。通常電力、充電・温度・OS・実際のリフレッシュレートを記録し、60Hzと90Hzで個別に測る。通常データは100件と1,000件、ストレスは10,000件。具体的な入力と手順は [計測契約](test-fixtures-v1.md) を使う。

| 対象 | 必須基準 |
| --- | --- |
| 通常のスクロール・220msの遷移 | 要求された各表示周期を分母に、95%以上で次の表示期限までにフレームを提示。60Hzは1/60秒、90Hzは1/90秒。欠落・未提示周期は失敗に数える |
| 通常のタップ・確定文字入力・削除 | 入力イベントの端末受信〜反映フレーム提示までのp95が100ms以内。操作受付と検索結果の両方を測る |
| 長い停止 | 操作・慣性中のQuietに起因する提示間隔が100ms以上にならない。処理起因ANR・クラッシュなし |
| 通信10秒待ち／遅いウィジェット併存 | 前記の通常フレーム・入力基準を維持する |
| 10,000件の検索 | 入力受付p95は100ms以内、正しい結果の提示p95は300ms以内。全候補・非表示を正しく処理する |
| 正常キャッシュからの起動 | 初回ホーム・一覧にキャッシュ内容を含める。全件再列挙の完了を待たない。初回プロセスのフォント等の初期化時間は別に記録 |
| 一覧・読み索引の追加メモリ | 規定の1,000件で、一覧・キー・検索結果・索引の保持に使うRustヒープ合計8MiB以下。生成中のピーク16MiB以下。再描画や遷移100回で同じ一覧コピーを増殖させない |

入力100msは入力の視覚的な受付と通常検索の結果を対象とし、ネットワークや外部アプリの成功完了まで100msを要求しない。1万件の結果300msは明示的な別基準で、入力受付まで300msへ緩めない。メモリ予算は製品全体のPSSと混同せず、全体PSSも併記して増分と計測範囲を明示する。

実際に90Hzで動かなかった試行は90Hzの合格としない。機器がない・OSの制約で測れない場合は未検証であり、基準を変更して成功扱いにしない。

## 14. 受け入れと変更管理

機能の代表環境はAPI 28・33・35のエミュレーターと基準実機API 33。最低APIでインストール・ホーム・IME・権限・再作成、代表APIで全Android連携・E2Eを実行する。すべてのAPIで未対応情報を架空の正常値にしない。性能は実機だけで判定する。

基準更新元は保存済みの0.3.0 APK。同じ署名・同じパッケージで更新し、ホーム、地域、表示、外部ウィジェットの登録と名前を保持する。0.4.0の追加設定も再更新試験で保持する。APK直配布と、`quiet-launcher.apk` 1ファイルを含むZIPを用意し、ZIPを展開後にAPKをインストールする説明を付ける。APK内部のres等を展開してインストールさせる導線にしない。

全要件には受け入れケースを対応付ける。既存の凍結済みテスト・期待値・判定ヘルパーは変更しない。足りないケースを本書から先に定義・凍結し、振る舞いの失敗を確認してから実装する。単なるコンパイル失敗、スクリーンショット保存、モック内の呼出成功だけでAndroid連携を合格にしない。要件の変更は理由と影響を示す次版として扱い、実装に合わせた期待値の変更で通さない。

合格記録は要件ID、ケースID、仕様・テスト・製品の版、入力、端末／API／ABI／IME／寸法、期待値、観測値、判定、ログ・画像・トレースを保持する。未実装・未実行・機器なしは未完了として残す。全件の必要な試験が合格するまで「全体要件充足」と報告しない。

- [OPPO Reno7 A公式仕様](https://www.oppo.com/jp/smartphones/series-reno/reno7-a/specs/): 基準機種の60／90Hz。実測時のモードは別途記録する。

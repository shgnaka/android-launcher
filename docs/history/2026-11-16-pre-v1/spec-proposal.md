更新日: 2026-11-16。[要件定義案](requirements.md) と [受け入れテスト計画案](acceptance-plan.md) を具体化するための提案。この文書で追加する詳細仕様・数値目標は、採用が決まるまで提案として扱う。実装・実行可能なテストは変更しない。

**優先する更新:** [2026-11-16の追加契約](contracts-2026-11-16.md) と [要件定義](requirements.md)。ホーム1画面・収容不可のエラー通知・常にホームへ戻る・通常管理からの非表示除外・読み対応検索・既存の画面時間定義の維持・メディア横切替は後続のユーザー指示で上書きされた。以下の旧案をそのまま最新の正解としてテストしない。

## 1. 確定済みの前提

- 非表示はホーム・アプリ一覧・検索結果のすべてに適用する。
- 一覧のアプリ名の長押しは、ホームへの追加／解除と非表示を選ぶメニューにする。
- 非表示中もホーム登録と順番を保持し、解除時に復元する。
- ユーザーの基準実機は **OPPO Reno7 A、Android 13**。

## 2. hide app の範囲と操作

非表示は **アプリ単位** とする。同じアプリに複数の起動項目がある場合は、まとめて隠す。同じ名前でも別のアプリは隠さない。

表示名の変更、アプリの更新、起動項目の追加、アンインストール後の再インストールでは、非表示を解除しない。Android のアプリ識別子を基準とし、表示名で同一性を判断しない。

長押しメニューは次の2操作を出す。

- 未登録なら「ホームに追加」、登録済みなら「ホームから外す」。
- 「アプリを非表示」。

長押ししただけでは起動・登録変更をしない。メニュー外のタップや戻る操作は、メニューを閉じるだけにする。非表示の選択後には確認ダイアログを追加せず、保存できた時点で表示に反映する。検索中に隠した場合も一覧に留まり、検索語は残して結果だけを更新する。

解除は **設定 → 非表示アプリ → 対象の「再表示」** から行う。ホームや通常の一覧には、非表示件数や解除用の特別な検索語を設けない。

管理画面ではアプリ名を表示し、同名の対象を区別する必要がある場合に補助情報を添える。アンインストール済みの記録は、最後に取得した名前と「未インストール」を表示する。未インストールでも非表示指定を解除できる。

Quiet 自身や Android の設定アプリを非表示にしても、背景の長押しによる Quiet の設定や、権限・標準ホームのシステム設定への導線は使えるようにする。非表示は通常のアプリ起動項目の表示・起動に適用し、システム全体のアプリロックにはしない。

## 3. 非表示中のホーム登録と並べ替え

非表示の項目のために、ホームに空白の枠は残さない。見える項目を詰めて表示する。再表示時の位置と、その間に行った他アプリの操作を両方保持する。

次の表示結果を受け入れ条件の案とする。B はホーム登録済みのアプリを表す。

| 初期登録順 | 操作 | B を再表示した後のホーム |
| --- | --- | --- |
| A, B, C | B を隠して再表示 | A, B, C |
| A, B, C | B を隠し、見える A, C を C, A へ並べ替える | C, B, A |
| A, B, C | B を隠し、A をホームから外す | B, C |
| A, B, C | B を隠し、D をホームの末尾に追加する | A, B, C, D |
| A, B, C, D | B と D を隠し、見える A, C を C, A へ並べ替える | C, B, A, D |

同じアプリの複数の起動項目をホームに登録していた場合、それぞれの登録位置を保持する。アプリの更新で登録した起動先そのものが消えた場合は、存在しない起動先を表示・起動せず、勝手に別の起動項目へ置き換えない。同じ起動先が復活した場合には登録を利用できる。

## 4. ウィジェットとの関係

アプリを隠しても、そのアプリの **登録済み外部ウィジェットは残す**。起動項目と情報表示を別に管理できるようにするためである。ウィジェットを消す場合は、ウィジェットの設定から削除する。

ウィジェット名は提供元が付けた名前を優先する。名前が空などで取得できない場合は、取得済みの名前、提供元アプリ名の順で補う。どれも不明なら不明と分かる短い表示にし、架空の名前で埋めない。

文字情報を読めない場合は、名前と「読み取り不可」などの短い状態に留め、技術的な詳細は設定にまとめる。許可や初回設定をキャンセルしたときは、その追加操作の仮登録を破棄し、既存のウィジェットは変更しない。

## 5. 検索と画面操作の細部

- 検索語とアプリ名は、Unicode NFKC、前後の空白削除、Unicode の小文字化を行って完全一致を判定する。ひらがなとカタカナ、読み仮名、別名を勝手に同一視しない。
- 一覧を開いたら IME を表示する。一覧のスクロールで IME を閉じ、入力欄のタップで再表示する。先頭へスクロールし直しただけでは IME を勝手に開かない。
- 日本語の変換中も入力中の文字で結果を更新し、変換確定後にも更新する。変換確定や Enter だけでアプリを自動起動しない。
- IME を閉じただけでは検索語を保持する。ホームへ戻った場合は検索語を消し、次に一覧を開いたら全表示対象を出す。
- アプリの長押しメニューを開く際は IME を閉じる。戻る操作はメニュー、設定、一覧など、その時点の操作対象を先に閉じる。
- 画面回転では表示中のページと検索語を保持する。プロセスの新規起動と明示的な HOME 操作ではホームを出す。権限画面から戻る場合は、その画面を開いた設定の位置へ戻す。

## 6. 天気

地域は **市区町村名で検索して候補を選択** する形を基本にする。同名の地域を区別できるよう、候補には都道府県・国などを添える。緯度・経度の直接入力は詳細設定に残す。自動現在地取得は追加しない。

通常表示は、例えば「晴れ 20°C · 07:30」のように、天気・気温・取得時刻を短く並べる。別日の取得時刻には日付も添える。

| 条件 | 振る舞いの案 |
| --- | --- |
| 地域未設定、表示オフ | ホームに天気欄を出さず、天気の取得も行わない |
| 地域を選択・変更 | 選んだ地域の情報をすぐ取得する。前の地域の数値を新しい地域の天気として出さない |
| 定期更新 | Quiet の前面表示中に、成功した取得から30分以上経過していたら取得。前面へ戻ったときにも判定する |
| 手動更新 | 取得時刻にかかわらず取得を要求する。同じ地域の取得中に連打しても同時に複数要求しない |
| 初回取得失敗 | 数値を作らず、設定済みならホームには「天気 —」程度の短い表示。理由・再試行は設定で扱う |
| 取得済み情報の更新失敗 | 前回の値と本当の取得時刻を保持する。詳細は設定に出し、取得時刻を成功したように更新しない |
| 自動取得の失敗後 | 前面表示中、5分以上空けて再試行する。手動更新はこの待ち時間に制限されない |
| 地域変更・解除後に古い要求が完了 | 古い地域の応答をホームへ反映しない |

取得から30分ちょうどなら更新対象、30分未満なら通常は再取得しない。非表示時の定期通信は行わない。地域の検索語と座標は天気に必要な通信にのみ使う。

## 7. スクリーンタイム

表示するのは **今日、画面が点灯し、ロックが解除され、操作可能だった時間の合計** とする。Quiet を見ていた時間だけに限定しない。バックグラウンドの音楽再生、画面消灯中、ロック中は含めない。

集計範囲は端末の現在のタイムゾーンでの午前0時から現在まで。タイムゾーン変更後は、そのタイムゾーンの今日として再集計する。表示は合計後に分未満を切り捨て、「1時間23分」の形式にする。

| 記録の例 | 期待する集計 |
| --- | --- |
| 前日23:50から操作可能、今日00:10に消灯 | 今日の分は10分 |
| 09:00から操作可能、09:20にロック、09:30に解除、09:40に消灯 | 30分 |
| 09:00から操作可能で、09:10現在も継続 | 10分 |
| 有効な区間が40秒ずつ2回 | 合計80秒なので表示は1分 |
| 同じ記録が重複 | その時間を二重に足さない |
| 許可なし・取得不能・履歴不足で一日の合計を確定できない | 0分とせず「—」。理由と権限操作は設定にまとめる |
| 一日分を確定でき、操作可能だった区間がない | 0分 |

ロック／点灯状態が不明な区間を推測で利用時間に足さない。許可を取り消した場合にも、以前の数値を現在の正常な集計として出し続けない。

## 8. 保存失敗・データ破損

非表示や再表示などの設定変更は、**保存に成功した時点で確定** する。保存に失敗したら操作前の状態を保ち、保存できなかったことを短く知らせる。再表示の保存に失敗した場合は非表示のままとする。

初回起動で設定が存在しない場合と、存在する設定を読めない場合を区別する。初回は通常の初期状態、破損・読み取り失敗時は次の動作を提案する。

- 非表示状態を確認できるまで、ホームのアプリ項目、通常一覧、検索結果を出さない。時計等の情報と Quiet の設定への操作は使える。
- 壊れた元データを残し、空の設定で自動上書きしない。
- 保存済みの正常なバックアップがあれば、設定の復旧画面から明示的に復元できるようにする。正常性を確認してから通常表示へ戻す。
- バックアップがない場合は初期化を選べるようにするが、自動では実行しない。初期化すると非表示指定とホーム登録等が失われることを、その操作画面で示す。

バックアップの保存先は端末内に限定する。復元が失敗した場合も元データを保持し、一覧を正常に復旧したように扱わない。

## 9. 性能と検証環境

基準実機はユーザー指定の **OPPO Reno7 A / Android 13**。公式仕様は最大90Hz、60Hz／90Hz可変としている。[OPPO公式仕様](https://www.oppo.com/jp/smartphones/series-reno/reno7-a/specs/)

次の数値は今回の目標案であり、達成済みという意味ではない。採用する場合は実装の合否を測る前に凍結し、実装が遅いことを理由に後から緩めない。

| 項目 | 合格基準の案 |
| --- | --- |
| 通常条件のアプリ数 | 100件と1,000件の制御された起動項目で測る。実在アプリを1,000個インストールすることは要求しない |
| スクロールと遷移 | 操作・慣性移動中の提示フレームの95%以上が、その表示モードの1周期の予算内。60Hzは約16.7ms、90Hzは約11.1ms |
| 入力への応答 | タップ、確定済み文字入力、削除から表示反映までの95パーセンタイルが100ms以内。日本語の変換候補を選ぶためにユーザーが待つ時間は含めない |
| 長い停止 | Quiet による処理で、操作中の表示が100ms以上止まらない |
| 待ち処理との同時実行 | 通信待ち、読み取りに時間がかかるウィジェットがあっても、通常条件の応答・スクロール基準を満たす |
| ストレス条件 | 10,000件でもクラッシュ・ANR・誤起動・検索結果の欠落がない。検索の表示反映は300ms以内。通常条件のフレーム時間と区別して記録する |

60Hzと90Hzの両方を測り、設定したモードと実際に動作したモードを記録する。OS側で60Hzとなっている計測を90Hzの合格には数えない。

比較条件は、releaseビルド、前面表示、通常の電力モード、文字サイズとデータを固定した状態とする。起動時の準備を終えた後、同じ10秒間の操作を5回実行し、各回で判定する。冷間起動や他アプリの割り込みは別に記録し、結果の悪い回を理由なく除外しない。操作手順、計測方法、判定対象の範囲もテスト凍結の対象とする。

Android 13 の基準実機に加え、Android 9 と代表 API のエミュレーターで機能の互換性を確認する。実機へ接続できない間は、性能を未検証として残す。

# 要件から作る受け入れテスト計画案

更新日: 2026-11-16。[要件定義案](requirements.md) を入力とする。全体の期待結果を設計する。追加契約に対する実行可能なテストは先行作成・凍結済みであり、全ケースの実装・検証完了を意味しない。

未確定部分の具体例と性能基準は [仕様案](spec-proposal.md) に整理した。採用後、A18・A25・A26・A29・A33・A36等へ具体例を反映してからテストを凍結する。基準実機はユーザー指定の OPPO Reno7 A / Android 13。

## 1. テストを先に固定する進め方

1. 要件と未確定事項をレビューし、要件 ID ごとに入力・操作・期待結果・対象環境を確定する。
2. 要件から期待値を手で定義したテストとフィクスチャを作る。現在のアプリの出力から期待値や画像の正解を生成しない。
3. テスト本文だけでなく、期待データ、比較用画像、判定ロジック、テスト用ヘルパー、実行対象一覧を凍結し、内容のハッシュと基準版を保存する。既存のテストも保護する。製品コードと同じファイルにある既存テストは、ファイル全体ではなくテスト部分を保護する。
4. 凍結したテストを実行する。未実装・不具合に対する失敗が要件違反を示すことを確認する。単なるビルドエラーを「正しく失敗した」証拠にしない。既に要件を満たすケースが最初から通ることは許容する。
5. 製品の実装を変更して同じテストを通す。期待値、テスト用の観測、実行設定、比較の許容幅を変えて通さない。
6. 要件単位の結果を記録し、凍結した内容に変更がないことを検査する。テスト件数やコードカバレッジで要件充足率を代用しない。

テストの削除、無効化、skip/ignore の追加、失敗の握りつぶし、必要な実行対象の除外、環境に応じた無条件成功はしない。テストに誤りがある場合も黙って修正せず、要件との矛盾を示して、別の仕様・テスト改訂として扱う。凍結後の実装中にはテストを変更しない。

既存の17件は回帰検査として維持する。ただし「既存のコードがこう動くから」という理由で追加テストの期待値を定めない。今回の要件に対する不足を以下の受け入れケースで補う。

## 2. テストの種類

| 種類 | 観測するもの |
| --- | --- |
| ロジック | 固定の入力に対する表示対象、検索結果、登録・順番、集計結果、保存・復元。時刻・地域・通信応答を制御する |
| 画面操作 | タップ、長押し、スワイプ、文字入力、戻る操作の結果。表示項目、表示領域、操作できる範囲を検査する。内部の private 関数を直接呼んで UI 操作の代わりにしない |
| Android 連携 | APK インストール、標準ホーム設定、起動先、実際の IME、権限・ウィジェットの許可画面、メディア操作先、描画済みウィンドウ、再作成を検査する |
| 実機性能 | 合意した基準実機・固定データ・release ビルドで、操作中のフレーム時間と応答時間を測り、事前の閾値で判定する |
| 配布・構成 | アプリ本体の言語、対応 API・ABI、APK の署名・更新インストール・配布アーカイブの中身、通信の範囲を検査する |

スクリーンショットを保存するだけの処理は、自動合否判定とは区別する。UI の自動判定に必要な観測方法と、要件から定めた許容範囲を凍結前に確立する。手動で見た項目を自動テストの合格として記録しない。

## 3. hide app の共通入力例

実在アプリの名前やその日のインストール状況に依存させず、次の制御されたデータを用意する。名前や識別子は試験データであり、製品内部のデータ形式は指定しない。

| 記号 | アプリの識別子 | 起動項目の識別子 | 表示名 |
| --- | --- | --- | --- |
| C1 | example.camera | main | Camera |
| C2 | example.camera | tools | Camera Tools |
| O1 | example.other | main | Camera |
| N1 | example.notes | main | メモ |

初期ホーム順を `[N1, C1, O1]` とする。非表示の指定がない初期状態から始める。Android 連携のケースでは、この条件を満たす試験アプリと、その実際の起動・インストール状態を使う。

| 操作 | 要件から定める期待結果 |
| --- | --- |
| C1 のメニューで非表示 | C1 と C2 がホーム・通常一覧・検索から消える。O1 と N1 は残る |
| `Camera` を検索 | O1 だけ。C1 は完全一致しても出ない |
| ` ＣＡＭＥＲＡ ` を検索 | 正規化案を採用した場合、O1 だけ |
| `Camera Tools` を検索 | 0件 |
| C1 を再表示 | ホームは元の `[N1, C1, O1]`。通常一覧には C1 と C2 が戻る |
| 別の検索方式に切り替える | 非表示の C1/C2 が通常の結果へ漏れない |

## 5. 検証記録と合格条件

要件 ID、ケース、試験データの版、凍結テストの版、製品コードの版、環境（Android API、ABI、画面、IME、実機機種）、期待結果、実際の結果、合否、ログ・画像・計測値を対応付ける。

全要件 ID を覆い、必要なロジック・画面・Android 連携・実機性能のケースがすべて合格した段階で全要件充足とする。環境がなく実行できない項目は未検証と記録し、デスクトップのモックだけで合格に置き換えない。実機性能をエミュレーターの所要時間で代用しない。

既存の `docs/android-test-result.json` は過去版の検証記録であり、今回の hide app または全要件の充足証拠ではない。

## 3. 画面と操作

幅240／320／360dp、高さ640dpの縦と幅640dp／高さ360dpの横、幅320dp／高さ320dpの分割を使う。文字80／100／160%、明暗の両方、上24dp・下24dpのシステム領域、追加の上40dp切り欠き、IME高280dpを組み合わせる。実Androidでは実測Insetsも記録する。

時計は2026-11-16 09:05 JSTを固定し、`09:05` と `2026年11月16日（月）`。09:06、翌日00:00、UTCへの変更は各期待値を手で固定する。端末時計の変更試験は隔離エミュレーターだけで行い、ユーザー実機の時計を無断変更しない。

収容境界は必要高さHに対して利用高さH−1／H／H＋1dpで判定する。設定オンの情報が未取得でも予約を含める。0件と複数件のホーム、情報全オフ、全アプリ非表示、収容不可の旧設定、非表示解除での超過を含める。超過ではエラーが詳細操作なしで見え、ファイル・登録・順序が変更されない。文字の省略と登録行の除外を別々に検査する。

上48dp／47dp、縦横比1.5の前後、下112dp／111dp、開始時先頭／途中、長押し499ms／500ms、移動9dp／10dp、タッチキャンセルと2本指を境界入力にする。スワイプのちょうど等号は移動判定を満たし、長押しは500ms以上かつ移動10dp未満に限る。縦横比1.5未満は遷移しない。

Back/HOME/回転/消灯/他アプリ/権限結果は要件第4節の表の各行を、ホーム・一覧・IME・長押しメニュー・設定・地域入力・読み入力・初期化確認から検査する。Backでキャンセルした未保存値は保持しない。保存完了済み値は戻さない。IMEの変換中・変換後と、明示的にIMEを閉じる操作を別ケースにする。

UIロジックは実際の入力イベントで操作し、描画文字・矩形・クリップ・操作可能性を観測する。AndroidではUI階層、OCR、フォアグラウンドActivity、描画済みSurfaceを組み合わせる。判定器が実文字を読めない・OCRに失敗した場合は観測失敗であり、期待値の変更や自動合格にしない。

## 4. 天気・画面時間

天気の試験時計を2026-11-16 09:00 JST、地点A=(35.0,135.0)、B=(34.0,136.0)とする。Aの正常観測は08:45、取得09:00、19.5°C、晴れ。表示は20°Cと09:00。−0.5°Cは−1°C。観測時刻を取得時刻に置き換えない。

成功後29分59秒は定期要求なし、30分00秒で要求。失敗後4分59秒は自動再試行なし、5分00秒で再試行。キャッシュ23時間59分59秒は古い値＋更新待ち、24時間00秒で `天気 —`。前日取得には日付を付ける。10秒期限、初回失敗、表示オフ、地域なし、手動連打、A→B→Aの完了順逆転、時計逆行、NaN・無限大・欠損、観測が10分超未来／3時間超過去を検査する。ネットワークのテスト応答は固定する。実通信の接続検査と内容の正解検査を混ぜない。

画面時間は状態付き取得結果と区間集計を分ける。固定したJST午前0時境界と09:00現在を使う。

| 入力 | 正解 |
| --- | --- |
| 前日23:50 On、今日00:10 Off | 今日10分 |
| 今日08:00 On、08:20 Off、08:30 On、08:40 Off | 今日30分 |
| 今日08:50 On、09:00現在もOn | 今日10分 |
| 40秒の既知区間を2回 | 合計80秒、表示1分 |
| 同じOn/Offの重複 | 単一区間として数える |
| 7日前まで境界不明、以後08:00 On〜08:20 Offだけ既知 | 20分の概算／履歴不足。完全集計と表示しない |
| API失敗・許可なし・状態不明の空履歴 | — |
| 境界からOffと確定、現在まで利用なし | 0分 |

7日前までの履歴の範囲は採用する情報量の上限で、保持するのは集計に必要な状態・区間だけ。生の利用履歴を永続化しない。23時間／25時間の暦日を持つタイムゾーンでは「今日」と固定86,400秒の「直近24時間」を別々に検査する。Resetで終了が不明な区間は計上しない。ロックだけではOn区間から除外しない。設定変更前の応答を遅らせ、表示範囲が逆戻りしないことを確認する。

## 5. メディアの提供元と正解

制御可能なRustの試験用プレーヤー2つを用意する。P1は曲A/B/C、初期はB、再生中、前／再生／一時停止／次に対応。P2は曲X/Y、初期X、一時停止、再生／一時停止／次に対応し、前は未対応。受信したコマンドと実状態の両方を観測できるようにする。

- 初回はP1。P1の次操作でCに変わり、P2はXのまま。
- 横スワイプでP2へ切替。スワイプ自体では双方にコマンドなし。P2の前操作は送信なし。再生でP2だけPLAYINGになる。
- セッション列挙順を逆にしてもP2を選択したまま。P2消失ならP1、両方消失なら欄なし。
- BUFFERING／CONNECTING、STOPPED、NONE、ERROR、曲名欠落、権限なし・取消・読取失敗、セッション消失と送信の競合を別々にする。
- 操作を受信しても状態を変えない提供元を使い、Quietが再生成功を捏造しないことを確認する。
- 実験用ラベル・曲名は固定。ユーザーの実メディア内容を試験ログへ取り込まない。

## 6. ウィジェット

承認済み最低ラインの固定提供元は既存の標準AppWidgetProvider資材。名前 `TEST PROVIDER`、本文 `QUIET WIDGET READY`。追加後とプロセス再起動後に両方がホーム画像にあり、削除後は両方ないことを検査する。既存の凍結済みE2E・フィクスチャを変更しない。

別の追加フィクスチャで、文字なし・説明文あり、画像のみ、同じ文字と説明の重複、非表示View、長文4,096文字超、512ノード超、設定必須、許可拒否、設定キャンセル、提供元削除、同名ラベルを検査する。この補助物も要件から作成・凍結した後に製品修正へ進む。更新の `STATE A`→`STATE B` は固定した受信イベントによるロジック・画面検査に用いる。別実提供元の動的更新E2Eは任意拡張であり、最低3点やv1.0の必須E2Eには追加しない。

- ホーム要約と設定全文を別に検査し、省略は明示する。名前不明と実ラベル「ウィジェット」を混同しない。
- 受信後2秒の更新、前面復帰後5秒の静的本文を観測する。提供元が新情報を送らないこととQuietが読取結果を反映しないことを分ける。
- 追加の各段階で終了・保存失敗、削除保存後のID解放失敗、削除後の遅い通知を注入し、既存登録と削除結果を保護する。
- キャンセル後にOSの仮IDが残らず、再試行できることを検査する。複数の正常項目と非対応1件を同時に置き、失敗の分離を検査する。
- 実行先は隔離エミュレーター。設定・標準ホーム・権限・テストIDを退避・後始末し、ユーザー実機へ破損・クラッシュ注入をしない。

## 7. 保存、キャッシュ、通信

旧0.3設定、追加項目を含む0.4設定、廃止メモを含む旧設定、非表示未指定、重複、境界値、不正な重要項目、未来の形式版（schema_version=2）、破損JSONを手で用意する。読み込み→保存→再起動後の意味を比較し、現在のシリアライズ出力を正解ファイルとして採取しない。

保存処理の検証・バックアップ作成・一時ファイル書込・同期・置換前後・ディレクトリ同期へ、エラーと停止を注入する。主設定が完全な旧版か新版であり、中途半端なJSONを成功扱いしないことを確認する。破損元の通常保存拒否、復旧失敗、正常バックアップなし、確認付き初期化の完了／キャンセル、連打・複数変更の順序を別ケースにする。

OS上のウィジェットIDとファイルの復旧は別の観測を使い、ID一覧を取得しただけで本文復元と判定しない。キャッシュは同世代で列挙0回、世代／言語／端末再起動の変更で再列挙、失敗でも正常一覧を保持。起動先の入れ替え後も登録した同じ識別子が起動する。非表示設定の読取失敗ではキャッシュからも名前を通常表示しない。

通信はテスト環境で宛先・要求の内容を捕捉する。天気オン・地域ありのOpen-Meteo座標取得以外を許さない。検索、非表示、メディア、画面時間、ウィジェット、診断ログの内容が要求に含まれないことを検査する。提供元の別UIDの通信はQuietの違反として数えない。ログとAndroidのバックアップ設定も検査する。

## 8. 性能プロトコル

### 固定データと環境

- N=100、1,000、10,000。識別子 `example.perf.app00000/Main`〜、表示名は番号5桁＋ `あいうえおかきくけこ` を6回繰り返した先頭59文字、合計64文字。番号で全件が異なる。iは0〜N−1、通常の一致語はi=floor(N/2)の表示名で、期待する一致はその1件。別データでは先頭10件だけ表示名を `カメラ` に置き換え、`kamera` の正解は先頭10識別子とする。CPU速度の違うエミュレーターで実機の合否を代用しない。
- 基準実機のreleaseビルド。文字100%、幅・高さは実機値、明暗は明るい、100件と1,000件を独立測定。追加で文字160%の誤操作・横はみ出し・操作可達性を検査する。
- 同じデータ、収まるホーム登録3件、天気・画面時間・メディア設定を固定する。依存待ち条件では同じUIを使い、天気応答10秒待ちと、UIスレッドを使わない提供元待ちを注入する。
- 機種、Androidビルド、APK SHA、電源状態、温度、表示設定と実動作Hz、IME、空きメモリ、データSHA、計測ツールの版を記録する。90Hzへの切替がOSにより抑制されたら未検証とする。

### 時間の端点と分母

入力は端末上の入力イベント時刻から、対応する視覚変化／正しい検索結果を含むフレームの実提示時刻まで。adbホスト側のコマンド開始や往復時間で置き換えない。外部アプリのネットワーク完了は入力応答から除外するが、Quietの受付・待機表示は含める。

AndroidのシステムトレースとQuietのフレーム・入力・結果世代の対応情報を使う。正常に動いているスクロール・慣性・遷移の間に要求された表示周期を分母とし、VSyncの提示期限を超えた周期・欠落周期を失敗に数える。提示されたフレームだけを分母にして欠落を隠さない。ユーザー操作もアニメーションもない静止時間はフレーム率の分母に入れない。

p95は遅延を昇順に並べたceil(0.95×件数)番目（1始まり）。ちょうど100ms／300msは遅延基準内。提示間隔ちょうど100msは長い停止として不合格。フレーム基準は95%以上。丸めてしきい値を動かさない。

### 手順

1. 起動・キャッシュ検証・フォント準備後、30秒ウォームアップ。冷間起動時間は別記録。
2. ホーム→一覧→Backを10回繰り返し、各220ms遷移を記録する。Nごと・60/90Hzごとに行う。
3. 一覧を10秒間、同じ軌道・速度の上下フリックで操作する試行を5回。各回でフレーム率・最大停止を判定する。スクロールでIMEを閉じる明示動作の後に記録を開始する。
4. 入力応答は1回につき20操作（固定完全一致語への貼付と空欄への削除を交互に行う）を5試行、各試行のp95を判定する。IMEの候補選択を待つユーザー時間は含めない。
5. 同じ測定を依存待ち条件で実行し、処理待ちによるUI停止を検査する。
6. 10,000件では入力受付と検索結果完了を分け、100ms／300msの各p95、正解集合、誤起動・ANR・クラッシュを検査する。
7. 別測定で一覧・索引を構築する割当を分類し、安定時8MiB／生成ピーク16MiBを検査する。画像・フォント・JVM等の除外範囲を明示し、全PSSを併記する。構築後100回遷移・検索で同じデータの保持量が増殖しないことを確認する。

各回が基準を満たすこと。悪い回だけを除外しない。着信等の外部割込みがあった回は無効理由と生ログを残して再実行し、繰返しのOS制約を製品の合格にすり替えない。計測オーバーヘッドを事前に比較し、計測設定・トレース分類・判定器・しきい値も製品実装の修正前に凍結する。

## 9. 証拠と状態

全ケースに仕様SHA、テストSHA、製品SHA、環境、期待値、観測値、成功／失敗／未実行／観測不能を記録する。画像だけの保存、APIを呼べたこと、試験提供元がインストールされたことだけでは描画・操作連携の合格としない。全要件のテスト化・実行は次工程であり、現在の34件と既存の3点E2Eは限定された証拠として引き継ぐ。

# レビュー待ちの切り分けと作業順

2026-11-17。agyの独立レビュー中に既存ログを整理したもの。製品・テスト・期待値は変更していない。以下の優先度は修正案で、レビュー結果により更新する。

## 最初に観測を確かめる項目

1. `tests/font_controls_v1.rs` の拡大拒否試験はEndキーを送信しているが、ログでは100%のまま。実際に160%を選択した証拠がない。製品の収容拒否不具合と数える前に、操作が成立しているか確認する。このファイルは執筆中で、固定済み本体とは別扱い。
2. A11は画面外の行を検索消去の代用にしている。A19はOCRの行中心がボタン外になる。A16は操作送信と保存完了の競合の可能性。詳細は `testing-observation-review.md`。元テストは保持し、別観測で確認する。
3. 最新の全体ログでは旧 `overflow_notice` も失敗している。初期登録アプリが描画されず、追加操作が出た段階で失敗しているため、収容エラー表示の失敗とはまだ言えない。非同期カタログ応答と初期データの関係を切り分ける。以前の34成功を最新結果として引用しない。
4. `requirements_v1` は以前102成功46失敗、後続ログでは103成功45失敗。変動した試験名と実行環境を比較し、件数差を実装修正による改善と扱わない。

## 環境と記録

`target/v1-run/summary.json` の後続実行はAPI33を実行し10成功9失敗、API28/35はその実行時に不在。API35の以前の19件は別ログで10成功9失敗。古いAPI35ログが同じディレクトリに残っているため、summaryの実行対象と突き合わせて読む必要がある。

実機性能は証拠不足。API28はadb接続不成立。ウィジェット最低3点はAPI35の以前の実行で成功したが、後続summaryではAPI35不在として未実行。この履歴を混ぜて単一の全環境合格表にしない。

次の実行器改訂では実行ごとに別の出力ディレクトリと、開始時刻・製品SHA・テストSHAを保存する案がある。固定済み実行器をレビュー中に変更せず、改訂対象として提案する。

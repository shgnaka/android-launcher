- `tests/overflow_notice.rs`: 1件。収容不可の追加を実際に操作し、理由が詳細展開なしで読めることと、以前の登録が保持されることを確認する。実装変更前は原因が見えず失敗した。
- `examples/widget_e2e.rs`: 提案中の最低合格ラインの実験。APK内の状態だけでなく、実際のウィジェット提供元・UI操作・画面OCRで判定する。

cargo run --offline --no-default-features --example check_contracts

結果: 既存17 + 追加12 + UI4 + エラー通知1 = **34件成功**。凍結テスト・既存テスト部分に変更なし。製品のコンパイル・書式・上記Clippyに合格。全対象の厳格Clippyには凍結済み試験コードのスタイル指摘が残るため、全対象の警告ゼロとは報告しない。テスト内容を変更して解消していない。

## 外部ウィジェットの実画面実験

Android API 35 / x86_64 / 720×1280、実行中のKVMエミュレーターで実施。試験用APKは標準の `android.appwidget.AppWidgetProvider` とリソースだけで作り、独自Java/Kotlinソースはない。エミュレーターの既存設定を退避し、試験後に復元する。実機を対象にしないガードを設けた。

```sh
cargo run --no-default-features --example build_widget_fixture
cargo run --no-default-features --example widget_e2e -- \
  --adb /path/to/adb --serial emulator-5554 \
  --ocr /path/to/tesseract --tessdata /path/to/tessdata
```

OCRには英語・日本語データが必要。今回のローカル環境では `/tmp/quiet-ocr/root` 以下にシステムを変更せず展開した。API 35 / Build Tools 35 / Java17 /ローカル署名鍵を使う。

| 固定された期待結果 | 実画面の判定 |
| --- | --- |
| 提供元の正しい名前 `TEST PROVIDER` と本文 `QUIET WIDGET READY` がホームにある | 成功 |
| force-stopして再起動しても同じ名前と本文がある | 成功 |
| 設定から削除後は両方とも画面にない | 成功 |

`target/widget-e2e/summary.json` と3枚のPNG・OCR結果に記録した。途中の失敗に対して、提供元のパッケージ可視性、完了済み読み取り結果の反映待ち、削除操作の可達性を製品側で修正した。同じ凍結済みE2Eを再実行し、成功した。

**この3点を最低合格ラインにするか、ユーザーへ確認中。正式採用前の実験として扱う。** 本文の動的更新、初期設定画面、許可取消、画像・独自描画・コレクション、他社提供元の互換性はこの成功だけでは保証しない。ホームの1画面制約はロジック・egui検査で確認しており、このOCR試験が全サイズのはみ出しを自動判定しているわけではない。

0.4.0 / versionCode 16778240 の arm64 APKをビルドし、従来と同じ署名で検証した。`dist/quiet-launcher-0.4.0.apk` が直接インストールするファイル。ダウンロード用ZIPには `quiet-launcher.apk` だけを入れ、抽出した内容とビルドAPKが同一であることを検査した。

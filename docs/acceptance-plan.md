# Quiet Launcher 全体受け入れ計画 v1.0

2026-11-16確定。[全体要件](requirements.md) と [固定入力・観測・計測契約](test-fixtures-v1.md) を入力とする。以前の「案」を本計画へ置き換える。既存の実行可能テストと凍結済み契約・フィクスチャは変更しない。新規ケースは期待結果を先に作成・凍結し、製品実装を変更する。

この計画の確定は、各ケースを実行済みという意味ではない。現時点の成果は既存34件・Android起動試験・承認済みウィジェット3点E2Eに限定される。詳細は [前回の検証記録](nov16-validation.md)。

## 1. 手順と保護

1. 本仕様から入力と期待値を手で定義し、試験用APK・応答・時間・操作手順・観測方法を用意する。
2. テスト本体、期待値、補助物、判定器、しきい値、対象環境、実行対象一覧のハッシュを記録して凍結する。製品出力から期待値を自動採取しない。
3. 振る舞いの不一致による失敗を確認する。インターフェース不足のコンパイルエラーだけをRedの証拠にしない。既に満たすケースは最初から成功してよい。
4. 製品コードだけを修正して同じ試験を実行する。期待値、比較許容幅、試験入力、試験対象を変えて成功にしない。
5. 要件ID・ケース・製品版・試験版・環境・期待値・観測値・判定・証拠を対応付ける。凍結物の変更がないことも確認する。

テストの削除・無効化・skip/ignore・例外握りつぶし・実行対象の除外・環境なしでの自動成功はしない。誤った試験が見つかっても実装中に黙って直さず、要件との不整合を示した別改訂として扱う。既存の製品内テストはテスト部分、外部試験・ヘルパーはファイル全体を保護する。

## 3. 環境別の必須範囲

| 環境 | 必須の検査 |
| --- | --- |
| Rustロジック／egui | 全純粋ロジック、保存障害注入、状態表、文字・矩形・入力の制御可能なケース。Android連携の代用にはしない |
| API28 x86_64 | インストール・起動・標準ホーム・基本入力と日本語IME・権限・ウィジェット登録／削除・再作成・Back/HOME・非対応状態 |
| API33 x86_64 | 全Android連携ケース。Android13のBack／IME／権限経路と試験用プレーヤー・ウィジェットを含む |
| API35 x86_64 | 全Android連携ケースと承認済み3点E2E。edge-to-edge／Insets／再作成を含む |
| OPPO Reno7 A / Android13 arm64 | 標準ホーム、IME、非表示、メディア、実ウィジェットの機能確認と全性能プロトコル。破損・強制終了注入や時計変更は隔離エミュレーターで実施 |

エミュレーターの取得不能機能は未検証として記録し、同じ要件を実機で確認する。構成上実行不能なら成功扱いにしない。対応範囲を後から縮めて試験を省かない。

## 4. 証拠と合否

各要件をケースへ対応付け、ケース群を個別入力へ展開して実行可能な試験を作る。表の行数や成功テスト件数を要件充足率へ換算しない。ロジック・実画面・実Android連携・実機性能の必要な証拠が揃った要件だけを合格とする。

画像の保存だけなら資料、OCRや矩形等の固定判定を通ったらその観測の自動成功、手動確認なら手動確認として分ける。計測器の故障や観測不能は未検証。仕様・テストの凍結、失敗証拠、製品修正、再実行結果を同じ要件で追えるようにする。

過去の `android-test-result.json`、`android-test-result-nov16.json`、`nov16-validation.md` は当時の版・範囲の記録。全体要件v1.0の達成記録へ書き換えない。
